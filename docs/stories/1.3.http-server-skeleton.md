# Story 1.3: HTTP Server 骨架

## Status: Approved

## Story

**As a** 开发者,
**I want** 使用 net/http 标准库搭建多端口 HTTP server 骨架，支持 graceful shutdown,
**so that** 后续 OCI Registry API、HTTP Proxy 和 Metrics 服务有统一的 server 生命周期管理。

## Acceptance Criteria

1. `curl http://localhost:5000/healthz` 返回 200 + `{"status":"ok"}`
2. `curl http://localhost:5000/readyz` 返回 200 + `{"status":"ready"}`
3. 服务收到 SIGTERM 后完成在途请求再退出（graceful shutdown）
4. 启动日志包含 listen address 和 port
5. Registry (:5000) 和 Metrics (:9090) 两个 HTTP server 独立运行

## Tasks / Subtasks

- [ ] Task 1: 创建 HTTP server 工具函数 (AC: 3, 4, 5)
  - [ ] 在 pkg/httpx/ 中创建 server.go，提供 ListenAndServe 和 graceful shutdown 辅助函数
  - [ ] 使用 errgroup 管理 server 生命周期

- [ ] Task 2: 实现 healthz/readyz handlers (AC: 1, 2)
  - [ ] GET /healthz → {"status":"ok"}
  - [ ] GET /readyz → {"status":"ready"}（后续可接入就绪探针）

- [ ] Task 3: 在 main.go 中启动 registry server + metrics server (AC: 4, 5)
  - [ ] 使用 errgroup 管理两个 server
  - [ ] 注册 healthz/readyz 到 registry server
  - [ ] metrics server 暂时只注册 healthz

- [ ] Task 4: 单元测试
  - [ ] 测试 healthz handler 返回正确 JSON
  - [ ] 测试 readyz handler 返回正确 JSON

## Dev Notes

### net/http Server 生命周期

```go
srv := &http.Server{Addr: addr, Handler: mux}

g.Go(func() error {
    slog.Info("server listening", "addr", addr)
    if err := srv.ListenAndServe(); err != http.ErrServerClosed {
        return err
    }
    return nil
})

g.Go(func() error {
    <-ctx.Done()
    return srv.Shutdown(context.Background())
})
```

### 路由注册

使用 Go 1.22+ 的 ServeMux 增强路由：
```go
mux := http.NewServeMux()
mux.HandleFunc("GET /healthz", handleHealthz)
mux.HandleFunc("GET /readyz", handleReadyz)
```
