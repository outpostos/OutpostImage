# Story 1.2: 配置管理

## Status: Approved

## Story

**As a** 运维工程师,
**I want** 通过 CLI 参数、环境变量和配置文件统一管理 OutpostImage 的运行配置,
**so that** 可以灵活适配不同的部署环境，包括静态节点列表的热更新。

## Acceptance Criteria

1. 服务启动时解析 CLI 参数并打印关键配置
2. 环境变量 `REGISTRY_ADDR=:6000` 覆盖默认值
3. `--peers-file` 指定的文件变更后 10 秒内自动重新加载
4. `--docker-root` 默认 `/var/lib/docker`
5. `--peers` 支持逗号分隔的节点列表
6. 配置验证：端口地址格式检查

## Dev Notes

### go-arg 扩展结构体

```go
type RegistryCmd struct {
    RegistryAddr string   `arg:"--registry-addr,env:REGISTRY_ADDR" default:":5000"`
    ProxyAddr    string   `arg:"--proxy-addr,env:PROXY_ADDR" default:":3128"`
    MetricsAddr  string   `arg:"--metrics-addr,env:METRICS_ADDR" default:":9090"`
    DockerRoot   string   `arg:"--docker-root,env:DOCKER_ROOT" default:"/var/lib/docker"`
    Peers        []string `arg:"--peers,env:PEERS,separate" help:"Static peer list (host:port)"`
    PeersFile    string   `arg:"--peers-file,env:PEERS_FILE" help:"Path to peers file for hot-reload"`
    LogLevel     string   `arg:"--log-level,env:LOG_LEVEL" default:"INFO"`
}
```

### Peers 文件格式

```
# 每行一个节点地址
192.168.1.10:5000
192.168.1.11:5000
# 注释行以 # 开头
```

### PeerWatcher 设计

PeerWatcher 在 `pkg/routing/` 中，提供线程安全的 peers 列表访问和变更通知。
使用 fsnotify 监听文件变更，变更后解析并原子更新内部 peers 列表。
